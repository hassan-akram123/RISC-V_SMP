# L2 Cache UVM Testbench

UVM verification environment for a 1 MB 8-way set-associative L2 cache with MESI coherence protocol, designed as part of the RISC-V Symmetric Multiprocessor project.

---

## Overview

The DUT is a split RTL design: a storage module (`L2_Cache`) and a controller FSM (`L2_Cache_Controller`). Together they implement a shared L2 cache that services snoop-bus requests from L1 caches and manages DRAM read/writeback traffic.

### Cache Geometry

| Parameter       | Value                        |
|-----------------|------------------------------|
| Capacity        | 1 MB                         |
| Ways            | 8                            |
| Sets            | 2048                         |
| Line size       | 64 B (512-bit)               |
| Address width   | 32-bit                       |
| Address mapping | `[31:17]` tag · `[16:6]` set · `[5:0]` byte offset |
| Replacement     | Tree-PLRU (7-bit per set)    |
| BRAM latency    | 1 cycle (pipelined)          |

### MESI States

| Encoding | State    | Meaning                        |
|----------|----------|--------------------------------|
| `2'b00`  | Invalid  | Line not present               |
| `2'b01`  | Shared   | Clean, multiple sharers allowed |
| `2'b10`  | Exclusive| Clean, only copy               |
| `2'b11`  | Modified | Dirty, only copy               |

## RTL Details

### L2_Cache (Storage)

Provides independent read/write interfaces for all controller operations:

| Interface           | Direction | Description                                   |
|---------------------|-----------|-----------------------------------------------|
| `l2_lookup_*`       | In/Out    | Tag-compare lookup (hit/miss + MESI state)    |
| `l2_store_*`        | In        | Sub-line (64-bit) write to a hit way          |
| `l2_fill_*`         | In        | Full 512-bit line fill (from DRAM or WB)      |
| `l2_set_state_*`    | In        | MESI state update without data change         |
| `l2_line_rd_*`      | In/Out    | Full 512-bit line read by address             |
| `l2_vmeta_*`        | In/Out    | Victim way metadata peek (tag/valid/MESI/dirty)|
| `l2_vline_rd_*`     | In/Out    | Victim way full line read by set+way index    |

Single-port BRAM per way. Port priority: **fill > store > vline_rd > lookup/line_rd**.

### L2_Cache_Controller (FSM)

20-state Moore FSM handling all bus protocol and coherence logic:

```
IDLE -> LOOKUP -> SNP_RESPOND
                     |-- hit  -> HIT_LINE_RD_REQ -> HIT_LINE_RD_WAIT -> SUPPLY -> UPDATE_STATE -> IDLE
                     |          (WB hit)          -> WB_RECV -> WB_FILL -> IDLE
                     \-- miss -> MISS_PICK_VICTIM -> MISS_VMETA_REQ -> MISS_VMETA_WAIT
                                                        |-- clean victim -> MEM_RD_REQ -> MEM_WAIT_RESP -> MISS_FILL -> MISS_LINE_RD_REQ -> ... -> SUPPLY/UPDATE_STATE -> IDLE
                                                        \-- dirty victim -> MISS_VLINE_REQ -> MISS_VLINE_WAIT -> MEM_WB_REQ -> MEM_RD_REQ -> ...
```

**Bus commands (3-bit encoding):**

| Command | Encoding | Description                           |
|---------|----------|---------------------------------------|
| GETS    | `3'b000` | Shared read request                   |
| GETM    | `3'b001` | Exclusive (modified) read request     |
| UPGR    | `3'b010` | Upgrade S→I (no data, already dirty)  |
| WB      | `3'b011` | Writeback dirty line into L2          |

## UVM Testbench Architecture

```
tb_top
└── hw_top  (DUT + l2_snoop_if)
    └── l2_subsystem (L2_Cache + L2_Cache_Controller)

uvm_test_top (l2_*_test)
└── l2_env
    ├── l2_snoop_agent  [active]
    │   ├── l2_snoop_sequencer
    │   ├── l2_snoop_driver      -> drives bus_req_*
    │   └── l2_snoop_monitor     -> observes all snoop transactions
    ├── l2_mem_agent    [reactive]
    │   ├── l2_mem_sequencer
    │   ├── l2_mem_responder     -> responds to mem_req with mem_resp_line
    │   └── l2_mem_monitor
    ├── l2_scoreboard
    └── l2_coverage
```

Both agents share the single `l2_snoop_if` virtual interface, retrieved from `uvm_config_db` under the key `"snoop_vif"`.

## Test Suite

| Test                    | Sequence              | Description                                                  |
|-------------------------|-----------------------|--------------------------------------------------------------|
| `l2_gets_single_test`   | `l2_gets_single_seq`  | One GETS, cold miss → fill in S state                        |
| `l2_getm_single_test`   | `l2_getm_single_seq`  | One GETM, cold miss → fill M (L2 stays I)                    |
| `l2_gets_hit_test`      | `l2_gets_hit_seq`     | GETS same address twice: miss then hit (S→S)                 |
| `l2_getm_hit_test`      | `l2_getm_hit_seq`     | GETS fills S, GETM hits and invalidates L2 (S→I)            |
| `l2_upgr_test`          | `l2_upgr_seq`         | GETS fills S, UPGR invalidates without data phase (S→I)      |
| `l2_wb_test`            | `l2_wb_seq`           | WB writes dirty line into L2 (I→M)                          |
| `l2_miss_test`          | `l2_miss_seq`         | 8 cold GETS misses to different sets                         |
| `l2_conflict_test`      | `l2_conflict_seq`     | 9 GETS to same set, exercises 8-way PLRU eviction            |
| `l2_dirty_evict_test`   | `l2_dirty_evict_seq`  | Fill dirty line, then conflict to force DRAM writeback        |
| `l2_delayed_mem_test`   | `l2_miss_seq` + delayed responder | Tests controller patience on slow DRAM (3–5 cycle delay) |
| `l2_mixed_test`         | `l2_mixed_seq`        | 20 random GETS/GETM/UPGR/WB transactions                     |
| `l2_cov_closure_test`   | `l2_cov_closure_seq`  | Methodically closes all functional coverage bins             |

## Running Simulations

Simulations use **Cadence Xcelium** (`xrun`). The compile file list is `run.f`.

### Quick start

```bash
# Run currently selected test (l2_dirty_evict_test as configured in run.f)
xrun -f run.f

# Run a specific test
xrun -f run.f +UVM_TESTNAME=l2_miss_test

# Run with higher verbosity
xrun -f run.f +UVM_TESTNAME=l2_mixed_test +UVM_VERBOSITY=UVM_MEDIUM

# Run with coverage (already enabled in run.f)
xrun -f run.f -covdut hw_top -covtest my_test_name
```

### Switching the active test

Edit the `+UVM_TESTNAME=` line in `run.f` (only one should be uncommented at a time):

```
//+UVM_TESTNAME=l2_gets_single_test
+UVM_TESTNAME=l2_miss_test
//+UVM_TESTNAME=l2_dirty_evict_test
```

### Coverage

Coverage is collected automatically (`-coverage all`). Results land in `cov_work/`. To merge and view:

```bash
# Launch Xcelium coverage browser
imc -load cov_work/scope
```

## Key Design Notes

- **No reset on metadata arrays**: Tag/valid/MESI/dirty arrays use `initial` block initialization instead of a reset flop to avoid massive reset fanout at synthesis time. Valid bits default to `0` (all invalid) on power-up.
- **Store context locking**: The storage module locks a store hit (set/way/word) in registers and stalls subsequent store lookups until the BRAM write completes, avoiding RAW hazards on single-port BRAM.
- **Behavioral BRAM model**: `tb/behav_model.sv` replaces the Xilinx `blk_mem_gen_1` IP so the testbench runs without an FPGA tool installation.
- **PLRU tree**: Each set has a 7-bit binary tree state. `plru_pick` traverses from root to leaf; `plru_update` marks the used path as "recently used" (flip bits toward opposite subtree).
